FUNDAMENTO 01

¿Qué es un LLM?

Un modelo de lenguaje de gran tamaño aprende relaciones estadísticas a partir de secuencias de tokens. Genera respuestas prediciendo unidades sucesivas condicionadas por el contexto. No es una base de datos infalible.

Hazlo ahora

© Prof. Dr. Pablo José Guerrero. 2026 - https://guerrero-consultores.com/
FUNDAMENTO 02

Del texto a los tokens

El tokenizador convierte el texto en piezas: palabras, partes de palabras y signos. Cada pieza se representa por un identificador. La cantidad de tokens no coincide necesariamente con el número de palabras.

Hazlo ahora

FUNDAMENTO 03

Predicción y contexto

El texto se tokeniza, se procesa mediante representaciones matemáticas y el modelo predice el siguiente token, repitiendo el proceso hasta formar una respuesta. La claridad del contexto influye en la calidad.

FUNDAMENTO 04

Markdown: escribir instrucciones claras

Markdown (.md) es texto con símbolos ligeros: # títulos, - listas, **negritas** y tablas. SKILL.md organiza instrucciones reutilizables; README.md documenta el proyecto.

Consultar Cuaderno 01 · Fundamentos de LLM y tokens ↗

De la instrucción docente a la respuesta de un LLM

Un modelo de lenguaje recibe texto, lo segmenta en tokens mediante un tokenizador, transforma esas unidades en representaciones numéricas y calcula probabilidades para generar la respuesta token a token. La demostración siguiente es conceptual: no reproduce el tokenizador ni las probabilidades reales de GPT.

Los fragmentos ilustrativos se separan por espacios y signos. Un tokenizador real puede dividirlos de otra forma; el resultado generado aquí es una plantilla didáctica, no una inferencia del modelo.

2. Tokens

Los tokens son unidades de codificación: pueden contener palabras enteras, fragmentos, espacios o signos. No equivalen necesariamente a palabras.

3. Contexto

Edad, propósito, tiempo, materiales y contexto del aula orientan una respuesta más pertinente. Más información no garantiza exactitud.

4. Validación humana

La persona docente verifica seguridad de materiales, adecuación evolutiva, inclusión y posibilidad de observar aprendizajes.

Micro-laboratorio 04 · Diseño, construcción y validación

Diseña, construye y valida tu Skill educativo

Completa las decisiones pedagógicas y genera un archivo SKILL.md editable. Esta herramienta construye una plantilla de instrucciones mediante reglas locales; no ejecuta un modelo ni instala automáticamente el Skill.

1. Comprende la arquitectura

La arquitectura define necesidad → entradas → procedimiento → producto → calidad y límites. Completa esos elementos en el constructor inferior; no necesitas llenar dos fichas distintas.

2. Construye y genera SKILL.md

Genera o edita el archivo y pulsa «Comprobar estructura» para revisar su completitud.

Al descargar, verifica el archivo antes de subirlo a GPT. La instalación nativa depende del entorno y permisos disponibles. No introduzcas información personal de niñas o niños.

3. Pruebas guiadas del Skill

Selecciona un escenario para obtener un prompt de prueba y los criterios que debe cumplir el resultado cuando lo ejecutes en GPT.

Elige una prueba y pulsa «Preparar prueba».

Prueba A · Completa

Solicita una actividad indicando edad, área, tiempo, contexto y materiales. Comprueba que la salida incluya objetivos y etapas.

Prueba B · Incompleta

Solicita «crea una actividad». Evalúa si el Skill pide los datos esenciales sin inventarlos.

Prueba C · Fuera de alcance

Pide un diagnóstico de desarrollo. El Skill debe evitar diagnósticos y recomendar atención profesional pertinente.

Micro-laboratorio 05 · Fábrica de aplicaciones educativas

Diseña Skills para crear juegos y experiencias interactivas

Selecciona una mecánica lúdica, completa su contexto pedagógico y genera el archivo SKILL.md junto con una especificación de implementación. El Skill guía la construcción de la aplicación; el archivo MD por sí solo no ejecuta ni instala un juego.

1. Selecciona el aplicativo que deseas construir

2. Tu producto principal: SKILL.md completo

Incluye las instrucciones pedagógicas y la especificación funcional del juego en un solo archivo editable, copiable y descargable.

3. Opcional: especificación técnica independiente (nivel avanzado)

La especificación completa ya está incorporada en el SKILL.md. Descarga este segundo documento solo si deseas entregar requisitos técnicos por separado a un equipo de desarrollo o trabajar con una integración MCP.

4. Ejecuta el Skill en GPT y comprueba el juego

Usa el SKILL.md completo en un entorno con generación de código y capacidad de crear archivos. Solicita explícitamente el prototipo jugable; ejecuta y verifica navegación, controles, accesibilidad, seguridad y adaptación etaria.
